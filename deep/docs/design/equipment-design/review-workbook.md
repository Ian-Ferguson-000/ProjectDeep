**All decisions below are blank.** Recommended means the author's proposed launch selection, not user approval. Mark exactly one of Keep, Revise, or Reject for each reviewed identity and record reasons or replacements. A kept reserve entry requires identifying the recommended entry it replaces unless you explicitly expand the release budget.

## Roster and production comparison

| Category | Recommended | Reserve | Proposed launch composition |
|---|---:|---:|---|
| Kits | 24 | 12 | Four per class, including six preserved standards |
| Supporting items | 48 | 12 | Six per class plus 12 shared |
| Relics | 36 | 12 | Six families of six |
| Total | 108 | 36 | 144 candidates described, 108 proposed for launch |

| Scope alternative | Kits | Ability slots described for launch | Tradeoff |
|---|---:|---:|---|
| Lean fallback | 18 (3/class) | 72 | Less kit breadth; retain 48 items and 36 relics only if each has supported uses |
| Recommended | 24 (4/class) | 96 | Three contrasting alternatives per class; substantial asset/interaction work |
| Promote every reserve kit | 36 (6/class) | 144 | 48 more slots; not recommended without production and playtest evidence |

Quality parity means clear controls, readable effects, real tradeoffs, good offer selection, and interesting combinations. Counts cannot establish it. There is no playtest evidence yet that four kits per class is optimal. The initial target is a reviewable design hypothesis.

## System decisions requiring your final selection

These questions are part of reviewing the proposal, not blockers to writing it. Defaults are fully described in the overview. Changing one may require revising affected entries before declaring the roster final.

| Decision | Proposed default | Your decision / notes |
|---|---|---|
| Content size | 24 kits / 48 items / 36 relics; reserve entries substitute | |
| Kit model | One complete four-action kit; no mixing individual abilities | |
| Acquisition | Choose owned starting kit and find replacements during expeditions | |
| Persistence | Recovered physical kits return to Hearth; items and relic effects expire | |
| Capacity | Six personal supporting items; four expedition relics; one carried spare kit | |
| Swap points | Cleared, safe rooms; preserve uses and health, clear kit state, apply cooldown lock | |
| Movement resource | Preserve standard runtime cost of one; new kits propose zero with longer cooldowns | |
| Standard Mage typing | Preserve current arcane Fireball; later decide whether to correct it to fire | |
| Standard Healer sustain | Preserve resource-funded renewable dash heal; review rest healing separately | |
| Standard wolf | Preserve observed no-health wolf baseline; new companions have explicit eligibility | |
| Summon bench behavior | New-kit summons suspend; existing wolf behavior remains an identified exception to review | |
| Relic ownership | Shared expedition charges; personal effect on current controlled adventurer | |

## Acceptance scenarios for design review

No gameplay tests are claimed for these unimplemented concepts. These are future evaluation scenarios, plus document checks that can be performed now.

| Scenario | Acceptance criterion |
|---|---|
| Standard fidelity | Four current actions, resource costs, and known runtime/text conflicts are recorded for every class. No silent balance fixes. |
| Distinctness | Explain each alternate in one sentence using at least two changed tactical dimensions. Reject pure elemental recolors or faster stat tiers. |
| Independent viability | Each kit can fight a lone boss with zero items/relics, including missing companion, empty magazine, absent field, or no marks. |
| Two build directions | Each kit lists two compatible item/relic paths with different emphases; note setup dependencies rather than imply guaranteed synergy. |
| Reward usefulness | Simulate a three-option offer for each recommended kit: at least one immediate match, no all-dormant reward, no compulsory rare enabler. |
| Short versus long run | Map the offer targets to each dungeon length. The player can form a build before the final fight without filling every slot. |
| Boss resistance | Trap/root/pull kits still deal damage against immovable bosses. No control loop, immunity bypass, or unconditional execution. |
| Damage fan-out | One fireball, pack command, or three-moth cast yields one proc budget. Echoes, reflection, thorns, and dots cannot trigger one another. |
| Healing loop | Repeat standard healing dash, overheal, potion conversion, and Tide Pearl: finite item/relic budget, no repeatable damage/protection engine. |
| Resource loop | Combine Equation, Whistle, Star, and Last Match: refund never exceeds spend, debt repaid first, no empty-cast income. |
| Cooldown loop | Pin cannot shorten itself, summon return, reload, or an action below the shared floor; check standard combo interactions explicitly. |
| Party switch | Swapping preserves relic uses and personal health/debts; no offscreen relic generation, free summon recovery, or refreshed death saves. |
| Safe kit swap | Preview dormant items; no healing, cooldown refresh, old field detonation, or resource refill. Resolve pending wounds before switching. |
| Summon replacement | Missing companion can be restored without resource deadlock. Despawn/overwrite is not death; health-bearing and finite-flock models stay distinct. |
| Economy loop | Relic-generated gold does not trigger other loot effects. Second picks, reservations, debts, and replacements cannot be sold or cycled for profit. |
| Lethal damage | One expedition save at most; no chained Phoenix/Ashen Undertaker saves, no saving via a barrier that appears after damage. |
| Visual load | Enemy telegraphs remain legible under two fire patches, two Notes, two hounds, or three moths. Use outlines/icons as well as color. |

## How to evaluate scope after approval

Future implementation should first establish one standard and one contrasting alternative per class before committing assets for the remaining alternatives. This is a suggested validation order, not authorization to begin. Compare identical encounter seeds with a no-item baseline and two named builds per kit. Record completion, health loss, action use, movement, resource starvation, damage source distribution, and pickup/decline reasons.

Watch for a kit that makes another obsolete, a reward declined because it never works, or a relic that removes boss interaction. Raw win-rate parity alone is insufficient: a slower deliberate kit may be successful while still feeling worse. Use player explanations of why they chose a kit, and whether they can describe its tradeoff without reading a wiki. Tune or cut redundant content before increasing count.

Assess per-class offer pools rather than the full global catalogue. For a first paper pass, enumerate every kit/item and kit/relic compatibility pair, mark Immediate / Conditional / Dormant, and inspect the conditional requirements for circular dependencies. For later playtests, prioritize heavy multi-hit, healing, resource, and summon combinations rather than claim exhaustive balance from a few random runs.
